- **Coverage**: share of sealed calls the local model answered; the rest would still go to the LLM.
- **Agreement on answered**: how often the local answer equals the label in the data, on answered calls only.
- **95% lower bound**: lower end of the 95% Wilson interval for that agreement. The verdict uses this, not the observed value.
- **Answering everything**: agreement if the local model never abstained. The gap to "agreement on answered" is what abstaining buys.
- **Latency**: median time to classify one text on the benchmark machine (Darwin arm64, Python 3.13.5); the fine-tuned model ran on the Apple GPU (MPS). An LLM API call typically takes hundreds of milliseconds.
- **Calls saved** per 1,000 equals coverage times 1,000. With the default assumptions ($0.50 per 1,000 calls, 3,000,000 calls a month, $20 a month to serve) the monthly saving is coverage × $1,500 − $20.

## How to read this honestly

- These are human-labelled public datasets. The human labels stand in for "what the LLM answered". A real LLM teacher is noisier in some ways and more consistent in others, so your numbers will differ. Run it on your own logs.
- One split and one seed per dataset: there are no error bars across seeds. The Wilson bound covers sampling error in the sealed split only.
- The abstain threshold is chosen right at the edge of the bar on the calibration split, so a sealed lower bound that lands just under the bar (for example 94.4% against 95%) is common and counts as FAIL. That is intended: the sealed test is a confirmation, not a formality.
- The sealed split of each dataset was scored once per model and bar. Nothing was tuned after looking at these numbers.
- Fine-tuning on a GPU is not bit-for-bit repeatable. An earlier fine-tune of the same Banking77 split reached 45.8% coverage at the 99% bar; the run recorded here reached 39.7%. Expect differences of that size between reruns.
